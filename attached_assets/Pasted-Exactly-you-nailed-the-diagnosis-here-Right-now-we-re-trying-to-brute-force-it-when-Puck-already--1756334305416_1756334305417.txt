What Puck Requires (Based on Official Docs)
1. Root Configuration Is Mandatory

Puck needs a root defined in your config to render anything—it's the canvas container where components live.

From the documentation:

The root is the top-level component within Puck. It … renders a single wrapper around your other components. 
puckeditor.com

Example shown:

root: {
  render: ({ children }) => <div>{children}</div>
}


If you don’t include a root, the editor has no entry point—hence the "No items" in the Outline and blank canvas. 
puckeditor.com

2. Correct Data Shape: root + content

Puck expects the page data to have two specific parts:

{
  content: [
    { type: "HeadingBlock", props: { /*...*/ } }
    // other blocks...
  ],
  root: {
    // optional fields and props
  }
}


In practice, Puck injects metadata-driven root.props when fields are defined, but always expects root and content structure. 
puckeditor.com

3. Add CSS and Imports

Don’t forget the visual layer:

Import Puck's CSS to enable drag-and-drop UI:

import "@measured/puck/puck.css";


Without it, the editor interface may render poorly or lack interactivity.
